# 比赛领域模块

## 覆盖路径

- `src/internal/domain/game`

## 聚合与规则

`Match` 保存主客队、比赛时间、地点和 `scheduled`、`in_progress`、`final`、`cancelled` 状态；状态只校验枚举合法性，允许任意修正。`Lineup` 以比赛、球队、种类和编号标识一个阵容聚合，校验阵容名称、球员、棒次、条目 ID 和单一守备位置的唯一性。`Play` 保存比赛内顺序、局次、打者、开局投手、前后局面，以及逐球、跑垒和守备结果。

Play 的前后局面保存出局数、主客队比分和垒上跑者。领域服务检查比赛内顺序和相邻局面连续性；逐球及跑垒、守备子结果按各自顺序保存。实体使用乐观版本并以 `deleted_at` 软删除。

## 服务与端口

写 `Service` 通过 `UnitOfWork` 在事务中验证球队、球员和比赛引用，创建、更新或软删除 Match、Lineup 和 Play，也可一次写入整场 `GameRecord`；删除比赛时显式软删除关联阵容、比赛过程及其子结果。读 `QueryService` 通过只读 Repository 返回恢复后的领域对象，支持比赛筛选、比赛详情、阵容、完整比赛过程和当前比分；当前比分取 sequence 最大的有效 Play 的结束局面，是否最终仅由 Match 状态决定。

开发 fixture 的已结束比赛保留双方首发与备用阵容，并提供一条九局下半刘备的再见一垒安打 Play：开局局面为两出局、二垒有人、4:4，结束局面为蜀汉 5:4，附带一条逐球记录和二垒跑者回本得分的跑垒结果，便于演示比赛详情与当前比分查询。

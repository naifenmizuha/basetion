# 比赛领域模块

## 覆盖路径

- `src/internal/domain/game`

## 聚合与写入规则

`Match` 保存主客队、赛程、地点和 `scheduled`、`in_progress`、`final`、`cancelled` 状态。`Lineup` 按比赛、球队、种类和编号标识，要求名称和条目非空、棒次和球员唯一，每名条目只能有一个守备位置。`Play` 保存比赛顺序、打者、开局投手、前后局面及逐球、跑垒、守备结果。所有实体和子结果使用 `deleted_at` 软删除，不维护乐观锁版本。

写 `Service` 通过比赛 UnitOfWork 验证球队和球员引用、检查 Play 相邻局面的连续性，并创建、替换或软删除比赛、阵容和 Play。删除比赛会在同一事务中显式软删除关联阵容与 Play；替换或删除 Play 会同步软删除其逐球、跑垒和守备子结果。

## 姓名化只读投影

`QueryService` 以 `MatchFilter` 提供五个批量只读入口：比赛目录、带最终比分和赛果的摘要、完整比赛记录、阵容和逐场球员表现。筛选支持最多两个参与球队精确名称、闭区间赛程和可选 `Limit`；结果按 `scheduled_at DESC, id DESC`，`Limit=0` 表示不限制。服务拒绝反向日期范围、负数限制和超过两个参与者。

比赛记录、阵容和表现中的球员均投影为姓名、球队名和背号，不向查询调用方泄漏 UUID。摘要从最后一条有效 Play 的结束比分得出；取消比赛为 `cancelled`，未结束或没有最终比分为 `pending`，已结束比赛依比分给出主胜、客胜或平局。

表现按比赛分别计算：进攻行来自有效 Play 与得分跑垒结果；投球行将打席归属最后一颗有效球的投手（没有有效球时归属开局投手），并分别汇总逐球、得分和明确标注的自责分；守备行只统计已保存的 `putout`、`assist`、`error`。`PerformanceLimitsView` 始终说明守备机会不可推断、自责分必须显式标记、未记录逐球事实不参与计算。没有事实的比赛仍返回空数组，不以零值虚构统计。

开发 fixture 提供一场蜀汉主场 5:4 获胜的已结束比赛、双方阵容以及带逐球、跑垒和守备结果的 Play，可用于目录、记录、阵容和表现查询。

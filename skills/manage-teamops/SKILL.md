# 使用 TeamOps

`teamops` 是球队结构化事实的唯一权威入口。不得根据对话、示例或一般棒球知识猜测具体球队数据，也不得生成模拟数据冒充查询结果。

## 查询流程

1. 涉及球队、球员、比赛、阵容、训练或表现分析事实时，先调用 `teamops` 的 `describe`，只请求与任务相关的模块。
2. 检查 `describe` 返回的模块名称和 `available` 状态。只有所需模块全部可用时，才能继续查询。
3. 调用 `query` 时使用最少模块和最窄数据范围，并提供定义了 `main(teamops)` 的受限 Lua 5.1 程序。
4. 只有工具成功返回的数据才能作为球队事实。回答中区分查询事实、由事实推导的判断和一般建议。

不需要球队数据模块的纯 Lua 计算可以直接使用 `query`，但仍必须定义 `main(teamops)`。

## 安全与失败处理

- TeamOps 只读；不得尝试写入、修改或删除任何数据。
- `roster.players` 必须提供 `team_id`，可用 `on_date` 查询历史名单，并可用 `position_any` 传入位置名称数组；省略 `on_date` 时读取当前名单。
- roster 球员结果中的手别和位置是具名字符串数组，效力日期为 `YYYY-MM-DD`，不要根据内部 bit flags 猜测字段值。
- 模块 `available=false` 时立即停止，明确告诉用户该数据能力尚未接入。
- 未知模块、参数错误、执行失败、超时或取消都不是成功结果；说明失败原因，不得补造结果。
- 不重复提交已经失败的同一查询，除非修正了明确的输入问题。
- 不调用 shell、数据库或文件系统绕过 `teamops`。
